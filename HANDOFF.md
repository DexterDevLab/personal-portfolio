# Handoff — Astro migration and redesign

Branch: `astro-migration` (the Next.js source stays on `main` until you merge).

## What changed

- **Framework:** Next.js 16 → **Astro 7.3.8**, static output with the Vercel adapter. Only `/api/contact` (POST) and `/contact/error` (no-JS status page) run as serverless functions. React, next-themes, Radix, react-hook-form, lucide-react, clsx, tailwind-merge, eslint-config-next are gone.
- **Positioning and copy:** "Frontend Developer / AI-accelerated" → **Freelance Web Developer** who builds, troubleshoots (WordPress & WooCommerce), launches, and maintains websites and web apps; designer colleague credited; AI-assisted development stated plainly in About and the case study. "40+ sites" and "open to full-time role" removed per your decision; "10+ years" and the availability badge kept.
- **Homepage structure:** Header (Work · Services · About · Contact · Résumé · *Discuss your project*) → Hero with the real Panda Central dashboard → Featured Panda Central block → Selected work (5 client sites, each "Development · Design by a designer colleague", live link) → Services (4) → How I work (4 steps) → About (portrait + concise stack list) → Contact (form, helpful-to-include list, direct email, GitHub, résumé) → Footer.
- **New route:** `/work/panda-central` case study, rendered from `src/content/work/panda-central.md`.
- **Content model:** projects are markdown files in `src/content/work/` validated by `src/content.config.ts`; site constants in `src/data/site.ts`; services/process in `src/data/`.
- **Theme:** dark + light, follows the OS by default, persisted in `localStorage.theme`, applied by an inline script before paint (no flash). No-JS visitors get the system theme via `light-dark()`.
- **Contact form:** native HTML form with progressive enhancement. With JS: zod validation (same messages as the server), JSON POST, inline success/error. Without JS: browser validation, form POST, 303 redirect to `/contact/sent` or `/contact/error?code=…`. Honeypot (`company`) returns a fake success and sends nothing. Delivery unchanged: Brevo transactional API, same sender/reply-to/subject.
- **Images:** screenshots and portrait moved to `src/assets` and served through `astro:assets` (AVIF/WebP, srcset, width/height, lazy below the fold; hero image eager with `fetchpriority=high`). All screenshots sit in the same "window" frame.
- **Brand assets:** static `favicon.svg`, `favicon-32.png`, `favicon-192.png`, `apple-touch-icon.png`, `og.png` generated by `npm run brand` (`scripts/generate-brand-assets.mjs`, satori + sharp) and committed.
- **SEO:** per-page title/description, canonical, OG/Twitter tags, `sitemap-index.xml` (`/` and `/work/panda-central`), `robots.txt`, JSON-LD (Person, WebSite, CreativeWork per project). `/sitemap.xml` 301s to `/sitemap-index.xml`.
- **Motion:** aurora glow, scroll reveals, a hover-only tilt on the hero frame; the cursor spotlight was dropped. Everything respects `prefers-reduced-motion`.
- **Docs:** `README.md` (run/build/edit map), `PRODUCT.md` (new positioning), `AGENTS.md` (Astro notes). `portfolio-plan.md` kept as history.

## Run and build

```bash
npm install
npm run dev      # http://localhost:4321 — API route works locally with .env.local
npm run check    # astro check
npm run build    # dist/ + .vercel/output/
```

## Deployment changes required

1. **Vercel → Project Settings → General → Framework Preset: set to "Astro"** (currently Next.js). Build command `astro build`, output directory left default. Node 24 runtime is fine.
2. Env vars `BREVO_API_KEY` and `CONTACT_EMAIL` already exist in the project; nothing to add.
3. After the first deploy: resubmit `https://dexteriglesia.com/sitemap-index.xml` in Search Console (the old `/sitemap.xml` redirects), and re-scrape the OG image in LinkedIn Post Inspector / Meta Sharing Debugger.
4. Merge `astro-migration` into `main` when you're happy with the Vercel preview.

## Verified

- `astro check`: 0 errors. `astro build`: succeeds; sitemap lists `/` and `/work/panda-central`; `.vercel/output/config.json` routes `/api/contact` and `/contact/error` to the function and everything else to static files.
- Local dev + curl: `GET /api/contact` → 405; invalid JSON payloads → 400 with the exact schema messages; honeypot → `{ok:true}` (nothing sent); form-encoded invalid submission → 303 to `/contact/error?code=invalid-name`, and that page renders the matching message; `/sitemap.xml` → 301; `/resume.pdf` → 200; unknown path → custom 404.
- Chrome at 1440px and 375px: homepage and case study render in both themes; no horizontal overflow; theme toggle persists across reload; mobile `<dialog>` menu opens, traps focus (close button focused), closes on Esc/backdrop/link; header gains its background after scroll; anchor targets land 80px below the top, clear of the 64px header, including when arriving from `/work/panda-central`; back-to-top appears after the hero; reveals trigger on scroll.
- Form in the browser: inline errors with the right messages and focus on the first invalid field; "Sending…" state; success message and reset (tested through the honeypot path so no real email was sent).

## Not verified / limitations

- **No real email was sent.** A live end-to-end send (JS path and no-JS path) still needs one real submission from you on the preview or production URL.
- **Lighthouse/PSI** not run; needs a deployed URL. The structure keeps the previous LCP decisions (eager hero image, no opacity entrance on text, no above-fold blur), but confirm on pagespeed.web.dev after deploy.
- `astro preview` doesn't work with the Vercel adapter, so the serverless routes were tested in `astro dev`, not in a production bundle. The Vercel preview deployment is the real test.
- The Geist fallback font metrics (`size-adjust` etc. in `global.css`) are approximations; if you ever see a visible shift when the font loads late, tweak them.
